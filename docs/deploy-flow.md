# Как выкатывать: порядок для команды (с 07385, ноябрь 2026)

Для Sana, Rosteria и Травницы. Что изменилось и почему — внизу, в «Что
поменялось». Технические детали — `docs/site-contract.md` §1–§2.

## Коротко

- CI идёт **только на PR** и проверяет **только то, чего коснулась правка**:
  правка фронта не запускает тесты сервера, правка сервера не собирает фронт.
- Один и тот же код **проверяется один раз**. После зелёного PR слияние в
  develop, PR develop → main и деплой тесты не повторяют.
- **Прод не ждёт стейдж.** Гейта «сначала зелёный smoke на stage» больше нет.
  Smoke и регрессия стейджа идут после каждого деплоя develop и шлют алерт,
  если упали.
- **Хотфиксы** едут на прод сами: без отмены запуска и без ручного обхода гейта.
- Деплой на сервере **не пересобирает то, что не менялось**: правка только
  сервера выкатывается без сборки фронта.
- Sana и Rosteria: метка **«в прод»** на PR в develop — после слияния код сам
  уедет на прод.

## Обычная задача — Sana и Rosteria

1. Ветка от `develop`: `<type>/<ID задачи>-<scope>-<описание>`.
2. PR в `develop`. CI: `ci / plan`, затем только нужные из `ci / lint`,
   `ci / unit`, `ci / integration`, `ci / build`. Ненужные — серые (skipped),
   это нормально: GitHub считает их пройденными.
3. Если задачу надо сразу на прод — **поставьте на PR метку «в прод» до
   слияния**.
4. Слияние PR → деплой stage (проверки пропускаются, если develop не ушёл
   вперёд) → сброс тестовых данных → smoke stage → регрессия stage.
5. На прод:
   - **с меткой «в прод»** — ничего делать не нужно. Сразу после проверок
     develop сам вливается в main, запускается деплой прода, в PR появляется
     комментарий «🚀 … деплой прода запущен». Автовыкатка не сработает, если в
     develop лежит чужое невыпущенное или есть конфликт: тогда в PR будет
     комментарий с причиной и алерт «АВТОВЫКАТКА НЕ СДЕЛАНА», а прод не
     тронут — выкатывайте пунктом ниже;
   - **без метки** — PR `develop → main` (merge-коммитом). CI на нём
     пропустится за секунды, если это тот же код, что уже проверен. Слияние →
     деплой прода → smoke прода.
6. Красный smoke или регрессия stage прод **не блокируют**, но это сигнал: не
   выкатывайте правку, пока не разобрались.

## Хотфикс — Sana и Rosteria

1. Ветка `hotfix/<ID>-…` от `main`, PR в `main`, CI.
2. Слияние → деплой прода → smoke прода. Ручной запуск с причиной обхода больше
   не нужен.
3. **Сразу после — PR `main → develop`.** Иначе develop расходится с main:
   следующий релиз будет перепроверяться целиком (дерево файлов другое) и
   автовыкатка может упереться в конфликт.

## Травница

Develop там несёт невыпущенный код, поэтому задачи едут на прод отдельно, без
слияния develop в main — метки «в прод» нет.

1. Ветка задачи. В develop — через `integration/<ID>-…-develop` (cherry-pick
   коммитов задачи на ветку от develop), PR в develop → деплой staging → smoke →
   регрессия → уборка заказов smoke.
2. На прод — PR ветки задачи (или `release/<ID>-…-main` с cherry-pick) в `main`.
   Слияние → деплой прода → smoke прода. На прод — только по явной команде на
   эту задачу.

## Что проверяется на какую правку

| Правка | Что идёт |
|---|---|
| только `server/` | lint, unit, integration сервера |
| только `client/` | lint, unit и сборка клиента |
| только `client/public/` (тексты, картинки, robots) | lint (с проверкой JSON переводов) и сборка клиента |
| `shared-test-cases/` (Sana) | обе стороны |
| `docs/`, `*.md`, `e2e/` | ничего |
| `.github/`, скрипты деплоя и CI, корневые package-файлы | всё |
| файл, не попавший ни в одно правило | всё — новый каталог не останется без проверок |

Правила каждого сайта — `.github/site-ci-areas.config.mjs` в его репозитории.
Что именно запустилось и почему — в сводке джоба `ci / plan`.

## Когда тесты всё-таки повторятся

Отметка «дерево проверено» (`site-ci/tested-tree`) привязана к содержимому
файлов. Тесты в деплое идут снова, если между проверкой PR и его слиянием в
ветку влили что-то ещё (содержимое уже другое), если код пришёл прямым push без
PR или если main ушёл от develop хотфиксами. Тогда проверяются только области,
затронутые разницей.

## Деплой на сервере

- Сборка — в отдельной папке. Сайт переключается только после успешной сборки и
  проверки живости, иначе откат и алерт (как было).
- Не менялись `package.json`/lock-файл и Node — `npm ci` не запускается.
  Не менялись `client/`, env-файл клиента и Node — фронт не собирается, берётся
  снимок прошлой сборки (не живой `.next`: в нём кэш страниц со старыми данными),
  sitemap генерируется заново.
- Полная пересборка «с нуля», если есть подозрение на старую сборку: Actions →
  Deploy → Run workflow → ветка → галочка `force-full-build`.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Красный `ci / …` в PR | чинить в ветке; ненужные проверки не запускаются, нужные — обязательны |
| Алерт «ТЕСТЫ НЕ ПРОШЛИ» в деплое | код влит, но не прошёл тесты (develop ушёл вперёд или прямой push) — на сервер ничего не уехало; чинить новым PR |
| Алерт «SMOKE / РЕГРЕССИЯ STAGE» | прод не тронут и не заблокирован; разобраться до выкатки этой правки |
| Алерт «SMOKE ПРОДА» | прод уже выкачен: смотреть отчёт Playwright в артефактах; откат — revert-PR в main или ручной запуск Deploy на прошлом коммите |
| Комментарий «Автовыкатка не сделана» | выкатить обычным PR `develop → main`; если мешает чужое невыпущенное — договориться с автором |
| Деплой «ДЕПЛОЙ УПАЛ» | deploy.sh сам откатил сайт и прислал отдельное сообщение; разбирать лог сборки |

## Что поменялось (07385)

| Было | Стало |
|---|---|
| CI на push ветки, на PR, на push develop/main — один коммит до 7 раз | CI только на PR; деплой проверяет только непроверенное |
| Все проверки на любую правку | Только затронутые области |
| Гейт сборки перед деплоем (сборка дважды на одной машине) | Сборку делает только deploy.sh |
| Прод ждёт smoke stage (~15 мин); хотфикс — ручной обход | Прод не ждёт stage; хотфикс — как обычный PR в main |
| `npm ci` и `next build` на каждый деплой | Только если менялись их входы |
| Интеграционные тесты: свой mongod на каждый файл, по одному | Один mongod, файлы параллельно (Sana 3 мин → ~1 мин) |
